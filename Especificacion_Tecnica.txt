ESPECIFICACIÓN DEL MOTOR
A Tu Lado  ·  Termómetro de riesgo en salud mental  ·  v1.0
Para el equipo de desarrollo
Este documento define, sin ambigüedad, qué debe programarse: instrumentos, puntuaciones, umbrales, reglas de anulación, estructura de datos y comportamiento esperado en cada ruta. Todo umbral aquí escrito proviene de la documentación oficial del instrumento que lo publica y no debe modificarse sin autorización del asesor clínico.
Tres reglas que no se negocian en el código
1. El riesgo suicida nunca se promedia. Las banderas anulan el resultado global; no suman a él.
2. Ningún umbral se ajusta por intuición. Cada constante tiene una fuente citada en este documento; cambiarla exige actualizar la fuente.
3. El plano gerencial nunca recibe texto libre ni puntajes individuales identificados. La separación se aplica en la capa de datos, no en la interfaz.
4. Un caso Rojo no se cierra por puntaje: se cierra únicamente con contacto humano verificado.

Codificación del registro diario
La escala de las caritas se almacena invertida para que un valor mayor signifique mayor malestar, igual que en el MDI: Excelente = 0, Bien = 1, Regular = 2, Mal = 3, Terrible = 4.
Esta codificación es la que alimenta la curva longitudinal del usuario. No confundirla con la escala del WHO-5, donde un valor mayor significa mayor bienestar.
LAS CUATRO REGLAS DE VIGILANCIA DIARIA
Se ejecutan cada vez que el usuario registra, y también en un proceso programado diario que detecta la ausencia de registro. Cualquiera que se active adelanta la aplicación del WHO-5 sin esperar al día 14.
const UMBRAL_DESVIACION = 1.0;   // puntos sobre la escala 0-4
const DIAS_PERSISTENCIA  = 3;
const SALTO_ABRUPTO      = 2;
const DIAS_SILENCIO      = 5;
function señalVigilancia(serie) {
  const base30  = media(ultimos(serie, 30));
  const movil7  = media(ultimos(serie, 7));
  // R1 · desviación de línea base
  if (serie.length >= 14 && (movil7 - base30) >= UMBRAL_DESVIACION)
      return 'R1_DESVIACION';
  // R2 · persistencia
  if (consecutivos(serie, v => v >= 3) >= DIAS_PERSISTENCIA)
      return 'R2_PERSISTENCIA';
  // R3 · caida abrupta sostenida 2 dias
  if (saltoSostenido(serie, SALTO_ABRUPTO, 2))
      return 'R3_CAIDA';
  // R4 · silencio tras patron regular
  if (teniaPatronRegular(serie) && diasSinRegistro(serie) >= DIAS_SILENCIO)
      return 'R4_SILENCIO';
  return null;
}
// R1 exige al menos 14 dias de historia para que base30 sea estable.
// Antes de ese punto solo operan R2, R3 y R4.
Límite de alcance de estas reglas
Los umbrales del WHO-5, del MDI y de Puchol provienen de sus instrumentos. Estos cuatro NO: son del equipo.
Por eso su efecto está acotado por diseño: disparan la aplicación de un instrumento y nunca asignan un nivel. En el código esto significa que señalVigilancia() jamás escribe en la tabla de clasificaciones — solo invoca abrirWHO5().
Se guardan como constantes de configuración, no incrustadas, porque se recalibrarán con los datos del piloto.
R4 tiene una regla de producto asociada: el mensaje al usuario debe acercarse, nunca reclamar. Nada de «llevas 5 días sin registrar».

CÁLCULO

// REGLA CRÍTICA: el umbral de 13 se evalúa sobre el CRUDO, no sobre escala.
// Fuente: instrucciones oficiales WHO-5, "la primera puntuación calculada".
// Aplicar 13 sobre la escala 0-100 haría el filtro inservible.
abrirMDI = (crudo < 13) || items.some(v => v <= 1)
El error que hay que evitar en la implementación
El corte de 13 vive en la escala cruda de 0 a 25, equivalente a 52 sobre 100. Si se compara contra la escala de 0 a 100, solo se detectaría a quien obtenga 12 de 100 o menos, es decir, prácticamente a nadie.
La segunda condición es independiente del total: un usuario puede obtener 15 de crudo y aun así abrir el MDI si respondió 0 o 1 en cualquier ítem individual.
REGLA DE CAMBIO LONGITUDINAL
Las instrucciones del instrumento establecen que una diferencia de diez puntos en la puntuación porcentual constituye un cambio significativo. La comparación solo es válida entre aplicaciones separadas por catorce días o más, porque la ventana de recuerdo del instrumento es de dos semanas.
Criterio según el origen de la aplicación
Aplicación PROGRAMADA (cada 14 días): se evalúan ambos criterios, el absoluto y el de cambio de 10 puntos.
Aplicación ADELANTADA por señal de vigilancia diaria: se evalúa SOLO el criterio absoluto. La comparación de 10 puntos no es válida entre aplicaciones separadas por menos de 14 días, porque la ventana de recuerdo del instrumento es de dos semanas y los periodos se traslapan.
El registro debe guardar el origen de cada aplicación: 'programada' o 'adelantada'.
const DIAS_MIN = 14;
const CAIDA_SIGNIFICATIVA = 10;   // puntos sobre la escala 0-100
function cambioSignificativo(actual, anterior) {
  if (!anterior) return false;
  const dias = diffDias(actual.fecha, anterior.fecha);
  if (dias < DIAS_MIN) return false;
  return (anterior.escala - actual.escala) >= CAIDA_SIGNIFICATIVA;
}
// Si devuelve true: elevar a AMARILLO como mínimo y abrir MDI,
// aunque el crudo siga por encima de 13.

Prohibido implementar el algoritmo diagnóstico
El MDI admite un segundo uso: aplicar los criterios ICD-10 y DSM-IV para emitir un diagnóstico de episodio depresivo. NO se implementa.
Razón: emitir un diagnóstico contradice el deslinde del producto y cambiaría su clasificación regulatoria. Solo se usa la escala de severidad.
Si alguien propone agregarlo, la respuesta es no, y esta línea es la referencia.
4
Capa 3 — ASQ y banderas de riesgo
El ítem 6 del MDI mide ideación pasiva: sentir que la vida no vale la pena. No mide intención. Para distinguirlas se aplica el ASQ del Instituto Nacional de Salud Mental de Estados Unidos, diseñado para tamizaje rápido por personal no especializado.
Por qué ASQ y no Columbia Protocol
El Columbia Protocol es gratuito, pero su gratuidad excluye los fines de lucro. Un producto que se vende por suscripción quedaría fuera de esa licencia, y el problema aparecería justo cuando el proyecto empiece a facturar.
El ASQ se publica sin costo y sin esa restricción, tiene versión oficial en español, se responde en menos de un minuto y sus reglas de interpretación son explícitas. Es la decisión correcta a largo plazo.
Confirmar por escrito las condiciones de uso con el NIMH antes de la primera factura, igual que con los demás instrumentos.

TRES OPCIONES DE RESPUESTA, NO DOS
El instrumento trata la negativa a responder como prueba positiva. En papel eso ocurre solo; en pantalla hay que darle un lugar explícito, o el usuario se ve forzado a mentir.
// Cada pregunta admite TRES valores. No dos.
type Respuesta = 'si' | 'no' | 'prefiero_no_contestar';
// 'prefiero_no_contestar' se procesa EXACTAMENTE igual que 'si'.
const esPositiva = r => r === 'si' || r === 'prefiero_no_contestar';
LÓGICA DE APLICACIÓN Y TRIAGE
function aplicarASQ(r) {
  const p1a4 = [r.p1, r.p2, r.p3, r.p4];
  // Prueba NEGATIVA: no se formula la pregunta 5.
  if (p1a4.every(x => x === 'no'))
      return { resultado: 'NEGATIVA', nivel: null };
  // Positiva: se formula la 5 para evaluar agudeza.
  const p5 = preguntar(5);
  // Negarse a contestar la 5 se trata como afirmativa:
  // ante la duda, criterio conservador.
  if (esPositiva(p5))
      return { resultado: 'POSITIVA_AGUDA', nivel: 'ROJO_AGUDO' };
  return { resultado: 'POSITIVA_NO_AGUDA', nivel: 'ROJO' };
}

La nota que el propio instrumento incluye
El ASQ advierte que el juicio clínico siempre puede anteponerse a una prueba negativa. En el sistema esto se implementa como una vía manual: el profesional del plano clínico puede elevar el nivel de un caso aunque el tamizaje haya salido negativo.
Esa vía debe existir en el código y quedar registrada en la auditoría. Un sistema que no permite al profesional contradecirlo se está colocando por encima del criterio clínico, que es exactamente lo que este proyecto declara no hacer.
4b
Protocolo de Rojo agudo a distancia
El ASQ fue diseñado para urgencias hospitalarias. Dos de sus instrucciones no son ejecutables a distancia: que la persona no puede retirarse hasta ser evaluada, y que se retiren los objetos peligrosos de la habitación. Forzar cualquiera de las dos sería coercitivo y podría ser contraproducente.
El cambio de sujeto que resuelve el problema
En la clínica se retiene a la PERSONA. En la aplicación se retiene el CASO.
El sistema no puede impedir que alguien cierre la pantalla, y no debe intentarlo. Lo que sí puede hacer es no cerrar el caso, no avanzar a otra cosa, y perseguir activamente el contacto humano hasta que se verifique.
La carga de reestablecer contacto pasa del usuario al sistema. Esa es la traducción correcta de la instrucción original.

Distinción por contexto de uso
Colaborador en sitio y en horario laboral: además de lo anterior, la empresa puede movilizar a la persona designada en el protocolo para acompañar físicamente, conforme a lo previsto en el consentimiento.
Usuario remoto o fuera de horario: la ruta es la línea de crisis de 24 horas más el contacto de emergencia registrado. Por eso los dos contactos son obligatorios al registro y editables en cualquier momento.
Ninguna de estas rutas se activa automáticamente sin acción del usuario, salvo el supuesto de riesgo inminente, que debe estar descrito de forma expresa en el consentimiento firmado.
Requisito de liberación
Este protocolo es el único componente del sistema que no debe liberarse sin aprobación por escrito del asesor clínico: textos de pantalla, redacción del plan de seguridad, y criterios de escalada.
El ASQ fue validado para aplicación presencial. Su uso a distancia es una adaptación legítima, pero es una adaptación: el equipo debe declararla como tal en la documentación en lugar de presentarla como uso estándar.

Regla de gobernanza de las ramas
No se programa una rama sin su ruta de canalización correspondiente. Tamizar algo que no se puede atender no es neutral: se le informa a la persona que tiene un problema y se le deja sola con él.
Cada rama requiere tres cosas antes de escribir código: el instrumento con su licencia verificada, el protocolo de escalada, y el recurso concreto al que se canaliza.
El acoso es un caso distinto: no es un trastorno sino una exposición. Se registra como marcador transversal que acompaña al nivel — «Naranja · marcador: acoso reportado» — porque la acción correcta no es canalizar a la persona sino intervenir el entorno.

FILTRO LÉXICO DEL TEXTO LIBRE
El sistema NO interpreta el texto. Aplica coincidencia contra una lista cerrada y versionada de términos críticos.
La lista es un componente clínico: la revisa y firma el asesor clínico, y se versiona en el repositorio junto al código.
Categorías: autolesión y muerte autoinfligida, métodos o medios letales, desesperanza absoluta, violencia sufrida o ejercida.
Un término detectado levanta bandera para revisión humana en el plano clínico. Nunca clasifica por sí solo, y nunca se expone al plano gerencial.
